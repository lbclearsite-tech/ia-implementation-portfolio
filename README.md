# AI Implementation Portfolio — Multi-Agent System
**Live demo:** https://ia-implementation-portfolio-xqwbzpgufmuwv8tb5ncckf.streamlit.app

A production-minded multi-agent system built by an **industrial technician** (quality technician, then industrialization technician by trade) transitioning into AI implementation. It applies industrial quality methods — FMEA, control plans, human-in-the-loop validation — to make LLM outputs **reliable, auditable, and safe to ship**.

The system has two working agents: one generates client quotes from structured input, the other answers questions strictly from the company's documentation. A central orchestrator routes each request to the right agent based on the user's intent.

---

## What it demonstrates

- **Reliability engineering for LLMs.** A golden test set, automated evaluations, guardrails, and structured logging — the same control-plan logic used on a production line, applied to non-deterministic AI outputs.
- **Structured, validated outputs.** Every generated quote passes schema validation (Pydantic) with automatic retry — *the prompt states intent, the code enforces the contract*.
- **Human-in-the-loop by design.** A validation gate stops every irreversible action until a human approves it. In testing, it caught a tax-rate discrepancy that automated validation could not.

## Architecture

```
                    User request
                         │
                         ▼
                 ┌───────────────┐
                 │  Orchestrator │  ← routing via enum-constrained tool use
                 │   (router)    │     logs every decision (audit trail)
                 └───────┬───────┘
              ┌──────────┼──────────┐
              ▼          ▼          ▼
        ┌─────────┐ ┌─────────┐ ┌────────┐
        │  Quote  │ │   RAG   │ │  none  │  ← refuses out-of-scope
        │  agent  │ │assistant│ │        │     requests cleanly
        └────┬────┘ └─────────┘ └────────┘
             ▼
     ┌───────────────┐
     │ Human approval│  ← no irreversible action without a human check
     │     gate      │
     └───────┬───────┘
             ▼
      JSON + PDF output
```

**Orchestrator** — routes each request to the right agent using an enum-constrained tool call, guaranteeing a valid decision at the API level. Every routing decision is logged for audit.

**Quote agent** (`generateur_devis.py`) — generates a structured BTP quote from targeted input, validates it against a Pydantic schema with automatic retry, and produces a clean JSON + PDF output. Company legal data is injected from config, never generated by the model.

**RAG assistant** (`assistant.py`) — answers questions using only a local document corpus (ChromaDB, multilingual embeddings). It cites its sources and refuses anything outside the corpus, which keeps hallucination out of scope by design.

---

## Reliability & quality control

- **Golden test set + automated evaluation** (`eval.py`) — a fixed set of expected behaviours, re-run after every change. A refactor is validated by identical scores before/after, not by manual checking.
- **Guardrails** — prompt-injection detection in monitoring mode: measure first, block later, once real data justifies a threshold.
- **Structured logging** (JSONL) — every request and every routing decision is traced. Test traffic and production traffic are tagged separately, so metrics stay interpretable.
- **Analysis scripts** — log analysers report request volume, injection rate, and routing distribution (coverage of the "none" path).

## Tech stack

- **Language:** Python 3.14
- **LLM:** Anthropic Claude API (tool use, enum-constrained outputs)
- **Validation:** Pydantic
- **RAG:** ChromaDB, sentence-transformers (`paraphrase-multilingual-MiniLM-L12-v2`), pypdf
- **PDF:** fpdf2
- **Logging:** JSONL

## Design principles

- **The prompt states intent; the code enforces the contract.** An LLM is not deterministic — only validation code guarantees a valid output.
- **Validate before use.** Every output is a potential non-conformity until checked. (FMEA reflex applied to LLMs.)
- **Human-in-the-loop before any client-facing output.** A non-negotiable design rule carried over from industrial quality.
- **Well-formed ≠ correct.** Schema validation proves structure; only a human check proves the content is right.
